处理哪些数据

你在应用前台按 START 开始录音后，腕记使用手表麦克风采集当前语音。停止录音后，音频会自动发送给你配置的服务，供识别并返回文字。应用不提供后台持续录音。

  • 音频和文字：用于完成你发起的语音转写和显示笔记。
  • 请求信息：录音编号、音频格式、时间和处理状态用于完成请求；参考服务器还保存音频文件摘要及设备令牌摘要，用于防止重复处理和限制访问次数。
  • 连接设置：HTTPS 服务地址和设备访问令牌通过 Garmin 应用设置配置和保存。令牌用于访问你选择的服务。

当前应用只声明麦克风输入和网络通信权限，不请求位置、健康数据或联系人权限。它不读取 Garmin 健康记录或系统中已有的录音库。

数据发往哪里

音频经可用的手表/手机通信路径发送到你填写的 HTTPS 地址。该服务的运营者及其识别服务提供方会接触完成转写所必需的数据。使用 Garmin Connect 时，其自身的数据处理适用 Garmin 的政策。

参考服务默认在同一部署环境中使用 faster-whisper 识别，不需要第三方转写 API 密钥，目前也没有由 WristNote 运营的默认生产服务。若部署者启用第三方识别接口，音频会被发送给其选择的提供方；处理地区、留存、日志及模型训练用途应以实际服务的说明和设置为准。

自建或私有服务并不等于离线处理，也不保证数据只在某一国家或地区保存。请先了解所选服务，再发送敏感内容。第三方识别服务的主密钥应保存在服务器，不应填入手表设置。

保存多久

在手表上

本次音频保存在应用运行内存中；退出应用会丢弃未完成的会话录音。手表本地保存最近 8 条转写文字，每条最多 1,200 个字符，以及笔记编号和创建时间。新笔记会替换超出数量限制的旧笔记，长文字会截短。

在参考服务器中

默认代码在内存中处理音频，不主动将录音写入数据库或音频文件。处理结束会清零应用持有的字节缓冲区并释放引用；运行库和解码器可能产生短暂副本，不能保证安全擦除全部物理内存。实际平台是否产生额外文件、日志或备份，须由部署者确认。

转写文字和请求记录的默认 API 可见期为 24 小时。到期后无法通过接口读取；运行中的服务会在已认证请求时和每小时清理过期活动记录。主动删除会使文字不可经接口读取，并保留限额与防重复处理所需的元数据直到到期。

这些操作属于逻辑删除。SQLite 空闲页、WAL 日志、磁盘快照或备份中可能残留数据，不保证立即物理擦除。实际日志和备份的保留、访问与清理由服务运营者决定。

参考代码不主动记录音频、转写文字或认证头。此说明不代表第三方服务、网络平台或运维配置具有相同的记录规则。

停止使用与删除

  • 停止本次录音：在处理界面按 BACK 取消，或退出应用。取消本地处理不能撤回已经到达服务器的数据。
  • 删除手表文字：使用笔记详情中的“删除这条笔记”，或“清空本地历史”。这些操作不会调用服务器删除接口。
  • 删除服务器文字：由实际服务运营者使用已认证的删除接口处理，或按其保留规则到期清理；日志、快照和备份需要分别处理。
  • 撤销访问：移除应用配置，并让服务运营者撤销或轮换设备令牌。也可按设备支持的方式撤销权限或卸载应用。

卸载手表应用不代表服务器中的数据已被删除。若你自行运营服务器，这些服务器管理操作由你控制；若使用他人的服务，请联系该运营者。

Privacy notice

Developer: WristNote. Effective date: November 5, 2026.

This notice covers the beta limited to testing by the publishing account owner and its reference server implementation. WristNote provides no default transcription service. You must configure your own HTTPS endpoint. The operator, processing location, additional logs and backups depend on the service you choose.

Data and permissions

Pressing START in the foreground begins microphone capture. Stopping the recording automatically uploads it to your configured endpoint for transcription. The app does not provide continuous background recording.

It processes audio, transcripts, recording IDs, format, timestamps and status. The reference server also stores audio-file and device-token hashes for duplicate protection and quotas. The endpoint URL and device access token are configured and saved through Garmin app settings.

The current app declares only audio-input and communication permissions. It does not request location, health-data or contact permissions, read Garmin health records, or access an existing system recording library.

Recipients

Audio travels through the available watch/phone connection to the HTTPS address you enter. Its operator and chosen recognition provider process the data needed for transcription. Garmin Connect’s own processing is governed by Garmin’s policies.

The reference server runs faster-whisper in the same deployment environment by default. There is no developer-operated default production service. If an operator enables a third-party recognizer, audio is sent to that provider. Its processing location, retention, logs and training use depend on the provider and deployment settings. A private or self-hosted endpoint does not imply offline or country-restricted processing. Provider master keys belong on the server, not on the watch.

Retention

The watch keeps current-session audio in application memory and discards unfinished session audio when the app exits. It saves the latest eight text notes, with up to 1,200 characters each, plus note IDs and creation times. Older notes are replaced and longer text is truncated.

The reference server processes audio in memory without intentionally saving audio files or database blobs. It clears its owned byte buffer and releases references after processing. Libraries and decoders may create temporary copies; secure erasure of all physical memory is not guaranteed. Hosting, diagnostics and backup behavior require separate operator review.

Transcripts and request records are accessible through the reference API for 24 hours. Expired records cannot be retrieved. While running, the server cleans expired active records on authenticated requests and hourly. An explicit deletion removes API access to the text; content-free quota and duplicate-protection metadata remains until expiry.

This is logical deletion, not a guarantee of immediate physical erasure. Data may remain in SQLite free pages, WAL files, snapshots or backups. Their retention and cleanup are controlled by the service operator. The reference code does not intentionally log audio, transcript text or authentication headers; other platform and operator logs may differ.

Control and deletion

Press BACK during processing or exit the app to cancel the watch session. This cannot retract data already received by a server. Delete a local note or clear local history from the app menu; these controls do not delete server content.

Ask the actual server operator to use the authenticated deletion endpoint and address logs or backups separately. Remove app settings and have the operator revoke or rotate the device token to withdraw access. You may also revoke supported device permissions or uninstall the app. Uninstallation does not delete server copies. For your own deployment, you control those server-management actions.

Information you choose to send by support email is used to handle that request; do not send passwords, tokens or sensitive recordings.
